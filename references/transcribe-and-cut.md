# 转写与剪 gap

主流水线的第 1、2 步。目标：得到一份可信的"文字 + 时间戳"，再把静音和重来剪干净，时间戳随之重算。

## 1. 转写（先告知，再动手）

开始转写之前，用一两句话告诉用户：
- 要转写哪个文件、多长；
- 用哪条路线（现有字幕 / 本地 Whisper / 云端），媒体是否会离开这台电脑；
- 大概耗时和费用（未知就如实说未知）。

得到用户同意后才开始。路线细节见 SKILL.md 的"转写路线"。

做法：
- 先把原片转成 1080p 的代理文件（proxy）再处理。4K 源文件解码慢、文件大，多出来的细节最后也会被丢掉。
- 需要逐字动画或精确剪辑时，请求逐字时间戳（word-level）。
- 整段转写会掩盖重来和口吃。更稳的做法：先按静音切成短句，**每句单独转写**，再从中挑最干净的一条。
- 静音段容易让 Whisper 编造重复句。凡是转写里出现可疑的重复，都对照真实音频确认。
- 转写结果存成项目本地文件（如 `transcript.json`），写明粒度（句 / 词）和来源。

## 2. 剪 gap

1. 用静音检测找出候选，例如：
   `ffmpeg -i in.mp4 -af silencedetect=noise=-35dB:d=0.4 -f null -`
   阈值和时长只是起点，要按录音环境调整，以本机 `ffmpeg` 实际输出为准。
2. **找干净的一条，用静音检测，不用转写时间戳**，因为转写时间戳会漂移。
3. 剪点前看一下首字之前约 0.4 秒的响度：一个短暂的小峰后面接一段空白，往往是转写看不出来的口吃（例如一个被吃掉的"我"）。
4. 把候选剪点列给用户确认（保留哪些、删哪些、停顿缩到多长），不要不声不响直接删。**先收紧停顿，再考虑提速**。
5. 用输入端 seek 逐段切（每段 `-ss a -to b -i`），再 concat。不要把一个输入接到几十个 `trim` 上：ffmpeg 会为每一段解码并缓冲整个文件，20 段能跑十几分钟。
6. 切完后重新转写一次成片，证明没有残留的口吃，并重算所有时间戳。剪辑、变速、去停顿之后，旧时间戳全部作废。
7. 保留源素材，所有输出写到新文件。

## 交付给下一步的数据契约

一份"最终音频 + 逐句（或逐词）时间戳"，并注明粒度。验证通过后才进入 HTML 预览。
